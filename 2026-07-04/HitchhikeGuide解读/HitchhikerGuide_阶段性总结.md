## 三、核心公式速查

### 3.1 PPO

```
概率比：r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)

裁剪目标：L_CLIP = E[min(r_t Â_t, clip(r_t, 1-ε, 1+ε) Â_t)]

完整损失：L = L_CLIP - c₁L_VF + c₂H(π)
```

### 3.2 DPO

```
DPO损失：L = -E[log σ(β(r̂_w - r̂_l))]

隐式奖励：r̂(x,y) = β·log(π_θ(y|x) / π_ref(y|x))

梯度：∇L = -β·σ(-r̂_w + r̂_l)·[∇logπ_θ(y_w) - ∇logπ_θ(y_l)]
```

### 3.3 GRPO

```
标准化优势：Â_i = (r_i - μ_G) / σ_G

群组均值：μ_G = (1/G) Σ_j r_j

目标：L = E[min(r_t Â_t, clip(r_t, 1±ε) Â_t)] - βD_KL[π_θ||π_ref]
```

### 3.4 DeepSeek-R1奖励

```
准确性奖励：r_acc = 1 if verify(y, y*) = True, else 0

格式奖励：r_fmt = 1 if valid tags, else 0

## 四、关键洞察总结

### 4.1 对齐算法洞察

```
对齐算法关键洞察
═══════════════════════════════════════════════════════════════════

1. 简化趋势
   PPO(4模型) → DPO(2模型) → GRPO(2模型，无价值网络)
   训练复杂度持续降低

2. 奖励设计
   - 可验证奖励（数学/代码）最有效
   - 简单二元奖励往往足够
   - 过程奖励模型（PRM）可能不是必需的（R1证明）

3. 群组采样
   - GRPO的群组采样提供自然的课程信号
   - 群组大小G=8是好的默认值
   - 自动聚焦在模型能力前沿

4. 蒸馏有效
   - 小模型从大模型蒸馏优于从头RL
   - 瓶颈是探索，不是表示
   - 推理能力可以转移

5. 涌现行为
   - RL可以涌现出复杂的元认知策略
   - 自我纠错、回溯、验证自发出现
   - "顿悟时刻"现象

═══════════════════════════════════════════════════════════════════
```

### 4.2 代理系统洞察

```
代理系统关键洞察
═══════════════════════════════════════════════════════════════════

1. 记忆是关键
   - LLM本质上是无状态的
   - 记忆系统是工程响应
   - 分层记忆（工作/情景/语义/程序）

2. 训练范式多样
   - STaR：自我引导
   - Reflexion：语言反思
   - ReAct：推理+行动
   - GRPO：群组优化

3. 环境提供反馈
   - 没有环境无法验证
   - 可验证奖励最有效
   - 代码/数学环境理想

4. 编排模式
   - ReAct循环最通用
   - 计划-执行适合复杂任务
   - 多代理适合大规模

5. 工具集成
   - MCP标准化接口
   - 安全沙盒必要
   - 缓存提高效率

═══════════════════════════════════════════════════════════════════
```

### 4.3 推理模型洞察

```
推理模型关键洞察
═══════════════════════════════════════════════════════════════════

1. 推理即搜索
   - 在部分解树上高效导航
   - 探索、回溯、验证
   - 计算分配是关键

2. 测试时缩放
   - 小模型 + 更多推理 ≈ 大模型
   - 计算-性能权衡转变
   - 可预测的缩放定律

3. R1突破
   - 纯GRPO + 结果奖励足够
   - 无需PRM
   - 自发涌现自我纠错

4. 隐藏推理
   - o1的隐藏推理令牌
   - 无格式约束
   - 防止风格奖励黑客

5. 蒸馏有效
   - 推理能力可转移到小模型
   - 优于从头RL
   - 瓶颈是探索

═══════════════════════════════════════════════════════════════════
```

## 五、实践指南

### 5.1 技术选型决策树

```
技术选型决策树
═══════════════════════════════════════════════════════════════════

场景1：对齐训练
├── 有可验证奖励（数学/代码）→ GRPO
├── 有成对偏好数据 → DPO或SimPO
├── 只有正/负反馈 → KTO
└── 需要最大灵活性 → PPO

场景2：代理开发
├── 代码代理 → GRPO + 执行反馈
├── 通用代理 → ReAct + 记忆系统
├── 需要长期记忆 → 分层记忆架构
└── 多代理系统 → 编排框架

场景3：推理增强
├── 简单推理 → CoT
├── 中等难度 → 自一致性
├── 复杂推理 → ToT或使用R1/o1
└── 需要可解释性 → 显式搜索方法

场景4：资源受限
├── 内存有限 → DPO或SimPO（无需价值网络）
├── 计算有限 → 2-GRPO或KTO
└── 时间有限 → 蒸馏而非从头训练

═══════════════════════════════════════════════════════════════════
```

```
最佳实践清单
