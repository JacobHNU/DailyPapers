## 一、为什么推理需要不同的RL方法

### 1.1 标准RLHF的局限

```
标准RLHF vs 推理RL
═══════════════════════════════════════════════════════════════════

标准RLHF：
- 优化单个标量奖励（完整响应质量）
- 即时反馈
- 短序列（几十到几百token）

推理任务的挑战：
├── 稀疏奖励
│   - 数学问题可能需要20个中间步骤
│   - 单一结果奖励无法为中间错误提供梯度信号
│
├── 长视野
│   - 推理链可跨越数百到数千token
│   - 严重的信用分配问题
│
├── 组合搜索
│   - 有效推理路径空间指数级大
│   - 模型必须学会高效搜索
│
└── 可验证性
    - 与主观文本质量不同，数学和逻辑正确性客观可验证
    - 允许自动奖励计算，无需人工标注

═══════════════════════════════════════════════════════════════════
```

### 1.2 核心洞察：推理即搜索问题

```
推理作为搜索问题
═══════════════════════════════════════════════════════════════════

多步推理可以框架化为在部分解树上的搜索问题：

树结构：
- 根节点：初始问题x
- 节点：推理状态s = (x, z_1, ..., z_k)（CoT前缀）
- 边：推理步骤z_{k+1}（一个token或句子）
- 叶子：带最终答案的完整解
- 价值函数：V(s)估计部分解的前景

RL for 推理教会模型：
- 高效导航这棵树
- 探索有前景的分支
- 从死胡同回溯
- 在最重要的地方分配计算

═══════════════════════════════════════════════════════════════════
```

### 1.3 链式思考：涌现能力 vs 训练能力

```
CoT的两种形式
═══════════════════════════════════════════════════════════════════

涌现CoT（Emergent CoT）：
- 来自上下文学习
- 需要大型基础模型（通常≥100B参数）
- 脆弱、对提示敏感
- 不能稳健泛化

训练CoT（Trained CoT）：
- 通过RL训练
- 模型内在地生成推理链
- 独立于提示风格
- 更长、更具探索性
- 展示自我纠正、回溯、验证等行为

DeepSeek-R1的"顿悟时刻"现象：
- 在RL训练中，模型自发开始重新考虑初始方法
- 使用"等等，让我重新考虑..."或"实际上，我认为我犯了个错误..."
- 这种自我纠正行为没有被明确训练
- 纯粹从最大化最终答案准确性的RL目标中涌现

═══════════════════════════════════════════════════════════════════
```

### 1.4 测试时计算缩放定律

```
测试时缩放定律
═══════════════════════════════════════════════════════════════════

核心发现：测试时计算与性能可预测地缩放

公式：
Accuracy(C_train, C_test) ≈ f(α·log(C_train) + β·log(C_test))

其中：
- C_train：训练计算（FLOPs）
- C_test：推理计算（生成的token数）
- f：单调函数
- α, β > 0：常数

含义：
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   更少推理计算 ◄─────────────────────────────► 更多推理计算     │
│                                                                 │
│   大模型 + 少推理  ≈  小模型 + 多推理                           │
│                                                                 │
│   这是计算-性能权衡的根本转变！                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

实践意义：
推理模型用训练计算换推理计算
- 不总是部署最大可能模型
- 而是部署更小的、推理能力强的模型
- 为困难问题分配更多token来"思考"

═══════════════════════════════════════════════════════════════════
```

### 2.2 链式思考（CoT）

```
链式思考（Chain-of-Thought）
═══════════════════════════════════════════════════════════════════

核心思想：模型生成中间推理步骤，将复杂问题分解为可管理的子问题

零样本CoT：
- 提示末尾添加"让我们逐步思考"
- 无需示例即可引发推理行为
- 需要足够大的模型（≥100B参数）

少样本CoT：
- 提供几个带显式推理轨迹的示例
- 允许更小的模型有效推理

形式化刻画：
p(y|x) = Σ_z p(y|x,z)·p(z|x) ≈ p(y|x,z*)·p(z*)

其中z* = (z_1, z_2, ..., z_T)是贪心推理链
对所有可能链的求和是不可处理的；标准CoT使用单个采样

局限性：
单链CoT是脆弱的：如果早期推理步骤错误，所有后续步骤都建立在有缺陷的基础上，没有恢复机制

═══════════════════════════════════════════════════════════════════
```

### 2.3 自一致性（多数投票）

```
自一致性（Self-Consistency）
═══════════════════════════════════════════════════════════════════

核心思想：采样多个独立推理链，对最终答案进行多数投票

公式：
ŷ = argmax_y Σ_{i=1}^N 1[y_i = y]

其中 (z_i, y_i) ~ p(·|x), T > 0

关键性质：
- 使用温度T > 0采样生成多样化链（通常T = 0.7-1.0）
- 链之间无交互 - 完全可并行
- 准确率随N单调增加（N ≈ 40后递减）
- GSM8K基准：CoT = 56.5%, 自一致性(N=40) = 74.4%

为什么多数投票有效：
如果模型有概率p > 0.5生成正确推理链，根据大数定律，多数投票随N→∞接近100%准确率

即使p = 0.3（模型通常错误），如果正确答案集中在一个值而错误答案多样，多数投票仍能恢复正确答案

这是测试时缩放的统计基础

═══════════════════════════════════════════════════════════════════
```

### 2.4 思维树（ToT）

```
思维树（Tree-of-Thoughts）
═══════════════════════════════════════════════════════════════════

核心思想：将CoT从线性链推广到树结构，使模型能够：
- 探索多条推理路径
- 评估中间状态
- 从无前景的分支回溯

形式化定义：
ToT = (G, E, V, π_θ, Search)

其中：
- G：思维生成器 - 产生b个候选下一步思维
- E：状态评估器 - 评分部分解V(s) ∈ {sure, maybe, impossible}
- π_θ：生成思维的语言模型
- Search：搜索算法（BFS或DFS）

搜索算法：

BFS（广度优先搜索）：
1. 为当前深度的每个节点生成b个候选思维
2. 用V(·)评估所有候选
3. 保留top-k最 promising的状态（束搜索）
4. 将所有k个状态推进到下一层
5. 重复直到找到解或达到深度限制

DFS（深度优先搜索）：
1. 为当前状态生成b个候选思维
2. 评估：如果V(s) = impossible，立即回溯
3. 如果V(s) = sure/maybe，递归更深入
4. 如果达到深度限制无解，回溯
5. 继续直到找到解或探索所有分支

计算成本：
LLM调用(BFS) = k·b（生成） + k·b（评估） = 2kb每层
总计 = 2kbd

对于24点游戏：b=3, k=2, d=3 → 36次LLM调用 vs 标准CoT的1次

结果：
在24点游戏上：ToT达到74%成功率 vs CoT的4%（使用GPT-4）

═══════════════════════════════════════════════════════════════════
```

### 2.5 思维图（GoT）

```
思维图（Graph-of-Thoughts）
═══════════════════════════════════════════════════════════════════

核心思想：将ToT从树扩展到有向无环图（DAG），引入关键能力：
合并来自不同分支的部分解

关键操作（超越ToT）：
├── 生成：从状态产生新思维（同ToT）
├── 聚合/合并：将多个思维合并为一个精炼思维 ← 这在树中不可能！
├── 精炼：基于反馈迭代改进思维
└── 评分：评估思维质量（同ToT的价值函数）

优势场景：
- 可分解的问题（排序、多文档综合、模块化代码）
- 需要综合多个视角的问题
- 可以并行处理子问题的任务

═══════════════════════════════════════════════════════════════════
```

### 2.6 蒙特卡洛树搜索（MCTS）用于推理

```
MCTS用于推理
═══════════════════════════════════════════════════════════════════

核心思想：使用学习的价值函数引导搜索，在探索和利用之间平衡

MCTS四个阶段：
1. 选择（Selection）
   - 从根节点选择最有前景的节点
   - 使用UCB（上置信界）公式平衡探索/利用

2. 扩展（Expansion）
   - 在选定节点生成新的推理步骤

3. 模拟（Simulation）
   - 从新节点执行rollout到终端状态
   - 或使用学习的价值函数估计

4. 反向传播（Backpropagation）
   - 将结果沿路径反向传播
   - 更新节点的访问计数和价值估计

在推理模型中的应用：
现代推理模型（DeepSeek-R1、OpenAI o1/o3）通过长链式思考生成执行隐式测试时缩放

"思考"令牌服务于类似MCTS rollout的功能：
- 模型探索多种方法
- 回溯（"等等，让我重新考虑..."）
- 验证中间步骤
- 为更难的子问题分配更多token

关键洞察：
R1/o1训练的关键是GRPO/RL教会模型在单次生成内执行这种隐式搜索
消除了对外部编排（ToT提示、MCTS基础设施）的需求
模型成为自己的搜索算法

═══════════════════════════════════════════════════════════════════
```

### 3.3 奖励设计

```
R1奖励设计
═══════════════════════════════════════════════════════════════════

关键设计选择：没有过程奖励模型（PRM）
使用两个简单的、自动计算的奖励：

1. 准确性奖励（Accuracy Reward）

   数学问题：
   r_acc(y, y*) = 1 如果 verify(y, y*) = True
                = 0 否则

   其中y是模型最终答案（从<answer>标签提取），y*是真实答案
   verify函数使用符号数学比较（如SymPy）处理等价形式

   代码问题：
   r_acc(y, T) = (1/|T|) Σ_{t∈T} 1[execute(y, t) = expected(t)]
   通过执行测试用例确定

2. 格式奖励（Format Reward）

   r_fmt(y) = 1 如果y有有效的<think>和<answer>标签
            = 0 否则

3. 组合奖励

   r(y, y*) = r_acc(y, y*) + λ_fmt · r_fmt(y)

   其中 λ_fmt = 0.1（足够小不主导，足够大防止格式崩溃）

═══════════════════════════════════════════════════════════════════
```

### 3.5 GRPO公式详解

```
R1中的GRPO公式
═══════════════════════════════════════════════════════════════════

群组采样和优势标准化：

对问题q，采样G个输出：{y_i}_{i=1}^G ~ π_θ(·|q)

使用奖励函数计算奖励{r_i}_{i=1}^G

响应i的标准化优势：
Â_i = (r_i - μ_r) / (σ_r + ε)

其中：
- μ_r = (1/G) Σ_{i=1}^G r_i（群组均值）
- σ_r = √((1/G) Σ_{i=1}^G (r_i - μ_r)²)（群组标准差）
- ε = 10⁻⁸（数值稳定性）

GRPO目标：

L_GRPO(θ) = -E_{q~D, {y_i}~π_θ(·|q)}[
    (1/G) Σ_{i=1}^G (1/|y_i|) Σ_{t=1}^{|y_i|}
        min(ρ_{i,t} Â_i, clip(ρ_{i,t}, 1-ε, 1+ε) Â_i)
    - β D_KL[π_θ || π_ref]
]

其中：
- ρ_{i,t} = π_θ(y_{i,t}|q, y_{i,<t}) / π_{θ_old}(y_{i,t}|q, y_{i,<t})
  是每令牌概率比
- ε ∈ {0.1, 0.2}是PPO裁剪参数
- β > 0控制KL惩罚强度
- |y_i|是响应i的长度（长度归一化防止对短响应的偏差）

KL惩罚公式：
D_KL[π_θ || π_ref] = E_{y~π_θ(·|q)}[Σ_{t=1}^{|y|} log(π_θ(y_t|q,y_{<t}) / π_ref(y_t|q,y_{<t}))]

实践中的近似（避免每步计算π_ref）：
D_KL[π_θ || π_ref] ≈ π_ref(y_t|q,y_{<t}) / π_θ(y_t|q,y_{<t})
                      - log(π_ref(y_t|q,y_{<t}) / π_θ(y_t|q,y_{<t})) - 1
（总是非负，当π_θ = π_ref时等于零）

═══════════════════════════════════════════════════════════════════
```

### 3.6 GRPO实践：群组大小和稳定性

```
GRPO实践细节
═══════════════════════════════════════════════════════════════════

R1中G = 8（每个问题采样8个响应）

这是关键超参数：
- 太小（G = 2）：优势估计高方差；训练噪声大
- 太大（G = 32）：计算成本线性增加；递减回报
- G = 8：经验上平衡方差减少和计算成本

群组采样提供自然的课程信号：
- 随着训练进行，模型平均奖励μ_r增加
- 方差σ_r减少
- 所有G个响应都正确（或都错误）的问题贡献零梯度
- 自然地将学习聚焦在模型能力前沿的问题上

═══════════════════════════════════════════════════════════════════
```

### 3.7 蒸馏：R1-Distill系列

```
R1-Distill系列
═══════════════════════════════════════════════════════════════════

主要实践贡献：证明推理能力可以蒸馏到更小的模型

R1-Distill系列（1.5B, 7B, 8B, 14B, 32B, 70B参数）训练方法：
1. 使用R1（671B）对大量问题集生成长CoT解
2. 过滤只保留正确解
3. 在这些解上微调更小的基础模型（Qwen2.5, Llama-3）

蒸馏 vs 小模型RL的惊人发现：
蒸馏在小模型上优于从头RL训练

DeepSeek-R1-Distill-Qwen-7B达到更高的MATH基准分数
比直接用GRPO训练的7B模型更高

这表明：
- 小模型缺乏通过RL探索发现推理策略的能力
- 但它们可以学习模仿大模型发现的推理策略
- 小模型的瓶颈是探索，不是表示

关于推理本质的问题：
小模型真正在"推理"吗？还是在推理链的表面形式上进行模式匹配？
经验上，蒸馏模型展示了一些对新问题类型的泛化
表明推理策略的真正内化，而非纯粹记忆

═══════════════════════════════════════════════════════════════════
```

### 4.2 隐藏推理令牌

```
o1的隐藏推理令牌
═══════════════════════════════════════════════════════════════════

定义性架构选择：使用隐藏推理令牌

模型生成内部链式思考（称为"推理轨迹"或"思考令牌"）
不向用户展示
只返回最终答案

影响：
1. 无格式约束
   - 隐藏推理可以使用任何格式
   - 包括草稿符号、伪代码、甚至非英语推理

2. 无风格奖励黑客
   - 用户永远看不到推理
   - 没有压力让它看起来"好"而不是有用

3. 专有保护
   - 推理过程不暴露
   - 防止直接模仿

训练过程：
- 描述为"训练模型使用RL推理"
- RL目标应用于完整序列（隐藏推理 + 最终答案）
- 仅对最终答案质量给予奖励

═══════════════════════════════════════════════════════════════════
```

### 4.3 过程奖励模型 vs 结果奖励模型

```
OpenAI的PRM方法
═══════════════════════════════════════════════════════════════════

OpenAI的方法被认为使用过程奖励模型（PRM）
与DeepSeek-R1的仅结果方法形成对比

这一推断基于：
- OpenAI发布的PRM研究（PRM800K数据集，"Let's Verify Step by Step"）
- o1系统卡对推理链RL训练的描述

结果奖励模型（ORM）：
R_ORM(q, y) ∈ [0,1]
- 对完整响应评分
- 对可验证任务（数学、代码）简化为精确匹配验证
- 对开放式任务，需要学习的奖励模型

过程奖励模型（PRM）：
R_PRM(q, y, t) ∈ [0,1]
- 对推理的每个步骤评分
- 提供更密集的训练信号
- 可以识别具体错误步骤

PRM优势：
- 更细粒度的反馈
- 更好的信用分配
- 可以检测中间错误

PRM劣势：
- 需要步骤级标注（昂贵）
- 可能引入步骤级奖励黑客
- 训练更复杂
```

## 六、关键方法的数学基础

### 6.1 蒙特卡洛树搜索用于推理

```
MCTS数学基础
═══════════════════════════════════════════════════════════════════

节点选择（UCB公式）：
a* = argmax_a [Q(s,a) + c·√(ln(N(s)) / N(s,a))]

其中：
- Q(s,a)：动作a在状态s的估计价值
- N(s)：状态s的访问次数
- N(s,a)：动作a在状态s的访问次数
- c：探索常数

价值估计：
Q(s,a) = (1/N(s,a)) Σ_{i=1}^{N(s,a)} R_i

其中R_i是第i次通过(s,a)的回报

反向传播：
从叶节点到根节点更新价值估计
Q(s,a) ← Q(s,a) + (R - Q(s,a)) / N(s,a)

═══════════════════════════════════════════════════════════════════
```

### 6.2 过程奖励模型训练

```
PRM训练方法
═══════════════════════════════════════════════════════════════════

数据收集：
对每个推理步骤标注正确/错误
需要专家标注或自动化验证

训练目标：
L_PRM = -Σ_{t=1}^T [y_t·log(R_PRM(q,y,t)) + (1-y_t)·log(1-R_PRM(q,y,t))]

其中y_t是步骤t的标签（正确=1，错误=0）

推理时使用：
- 选择PRM分数最高的推理路径
- 在搜索中剪枝低分路径
- 作为RL的奖励信号

═══════════════════════════════════════════════════════════════════
```

## 七、最佳实践总结

### 7.1 推理模型训练最佳实践

```
推理模型训练最佳实践
═══════════════════════════════════════════════════════════════════

1. 冷启动SFT
   - 保持数据集小（数千示例）
   - 只建立格式，不限制推理风格
   - 使用多样化的推理示例

2. 奖励设计
   - 优先使用可验证奖励（数学、代码）
   - 简单的二元奖励通常足够
   - 避免复杂的多目标奖励

3. RL方法选择
   - GRPO是当前最佳选择
   - 群组大小G=8是好的默认值
   - 监控群组奖励分布

4. 课程学习
   - 过滤提示到20-80%通过率
   - 定期重新过滤（每500步）
   - 让模型自然聚焦在能力前沿

5. 蒸馏
   - 对小模型，蒸馏优于从头RL
   - 使用大模型生成高质量推理链
   - 过滤只保留正确解

6. 评估
   - 使用多样化基准
   - 包含分布外问题
   - 监控推理链质量

═══════════════════════════════════════════════════════════════════
```

### 7.2 测试时缩放最佳实践

```
测试时缩放最佳实践
═══════════════════════════════════════════════════════════════════

1. 方法选择
   - 简单问题 → CoT
   - 中等难度 → 自一致性（N=10-40）
   - 需要规划 → ToT
   - 使用R1/o1模型 → 隐式缩放

2. 采样策略
   - 使用温度T=0.7-1.0生成多样性
   - 对自一致性，N=40通常足够
   - 对ToT，束宽k=2-5，分支b=3-5

3. 计算预算
   - 评估计算成本 vs 准确率提升
   - 小模型 + 更多推理有时优于大模型 + 少推理
   - 根据问题难度动态分配计算

4. 验证机制
   - 对多数投票，确保答案多样性
   - 对ToT/GoT，使用可靠的价值函数
   - 考虑多重验证（投票 + 价值函数）

5. 缓存和复用
   - 缓存常见推理模式
   - 复用成功的推理轨迹
   - 建立推理策略库

═══════════════════════════════════════════════════════════════════
```
