## 一、LLM工作原理

### 1.1 四个关键阶段

```
LLM管道：文本→文本
═══════════════════════════════════════════════════════════════════

原始文本 → 分词器 → 令牌ID → 嵌入层 → Transformer层(×L) → 词汇Logits → 解码 → 输出文本
                                                              ↑
                                                              └── 自回归循环（将令牌追加到输入）

四个关键阶段：

1. 分词（Tokenization）
   - 原始文本分割为子词单元
   - "unhappiness" → ["un", "happiness"]
   - 词汇表大小：32K-128K tokens

2. 嵌入（Embedding）
   - 每个令牌ID索引到学习的嵌入表
   - 产生d维密集向量（通常d=4096）
   - 相似词获得相似向量

3. 上下文处理（Contextual Processing）
   - Transformer栈并行处理所有嵌入
   - 使用自注意力让每个位置"读取"所有其他位置
   - 经过L层后，每个位置编码丰富的上下文信息

4. 预测（Prediction）
   - 最终隐藏状态投影到完整词汇表的概率分布
   - 解码策略选择下一个令牌

═══════════════════════════════════════════════════════════════════
```

### 1.2 分词（Tokenization）

```
分词方法对比
═══════════════════════════════════════════════════════════════════

粒度      │ 词汇表大小 │ 序列长度 │ 问题
──────────┼────────────┼──────────┼──────────────────────────────
字符级    │ ~256       │ 非常长   │ 注意力成本O(n²)；难以学习长程语义
词级      │ ~500K+     │ 短       │ 无法处理罕见/新词；巨大嵌入表
子词级    │ 32K-128K   │ 中等     │ 最佳权衡：短序列、开放词汇

BPE（字节对编码）算法：
1. 从单个字符（字节）的词汇表开始
2. 统计训练语料中所有相邻符号对
3. 将最频繁的对合并为新符号
4. 重复步骤2-3 k次（直到达到所需词汇表大小）

其他分词方法：
├── WordPiece：类似BPE但最大化训练数据似然（BERT使用）
├── Unigram LM：从大词汇表开始，按似然影响修剪（T5使用）
└── Byte-level BPE：在原始字节上的BPE（GPT-2+使用）

最佳实践：
├── 词汇表大小：32K最小；128K支持更好的多语言和代码处理
├── 特殊令牌：<bos>, <eos>, <pad>, <unk>
├── 数字：考虑数位级分词以支持算术推理
└── 代码：确保空白（缩进）被高效分词

═══════════════════════════════════════════════════════════════════
```

```

### 2.2 自注意力机制

```
自注意力机制
═══════════════════════════════════════════════════════════════════

缩放点积注意力：

给定输入序列 X ∈ R^{n×d}，计算：
Q = XW_Q, K = XW_K, V = XW_V

Attention(Q,K,V) = softmax(QK^T / √d_k + M) V

其中M是因果掩码（自回归模型）：
M_ij = 0 如果 i ≥ j（可以关注）
M_ij = -∞ 如果 i < j（未来令牌 - 阻止）

直觉：每个令牌"关注"所有先前令牌，基于查询-键相似性计算其值的加权平均

计算复杂度：
- 标准注意力：O(n²) 内存和计算
- 这是长序列的瓶颈

═══════════════════════════════════════════════════════════════════
```

### 2.3 多头注意力

```
多头注意力
═══════════════════════════════════════════════════════════════════

核心思想：让模型同时关注不同位置的不同表示子空间

MultiHead(Q,K,V) = Concat(head_1, ..., head_h) W_O

其中 head_i = Attention(QW_Q_i, KW_K_i, VW_V_i)

参数：
- h个头（通常h=32或更多）
- 每个头的维度 d_k = d_model / h
- 总计算量与单头注意力相同

优势：
- 不同头学习不同的关注模式
- 某些头关注局部语法
- 某些头关注长程依赖
- 某些头关注特定实体

═══════════════════════════════════════════════════════════════════
```

### 2.4 位置编码

```
位置编码方法
═══════════════════════════════════════════════════════════════════

问题：自注意力是排列不变的，需要注入位置信息

方法1：正弦位置编码（原始Transformer）
PE(pos, 2i) = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

方法2：学习的位置嵌入
- 为每个位置学习一个嵌入向量
- 限制最大序列长度

方法3：RoPE（旋转位置编码）← 现代LLM主流
- 将位置信息编码为旋转矩阵
- 相对位置通过旋转角度差捕获
- 支持长度外推

方法4：ALiBi（注意力线性偏置）
- 直接在注意力分数上添加线性偏置
- 无需学习的位置嵌入
- 良好的长度外推

RoPE公式：
q_m = R_Θ,m · q
k_n = R_Θ,n · k
q_m^T k_n = q^T R_Θ,m-n k（相对位置）

═══════════════════════════════════════════════════════════════════
```

### 2.5 前馈网络（FFN）

```
前馈网络
═══════════════════════════════════════════════════════════════════

标准FFN：
FFN(x) = W_2 · σ(W_1 x + b_1) + b_2

其中：
- W_1 ∈ R^{d×4d}（扩展）
- W_2 ∈ R^{4d×d}（压缩）
- σ通常是ReLU或GELU

SwiGLU变体（Llama、Mistral使用）：
SwiGLU(x) = W_2 · (Swish(W_1 x) ⊙ W_3 x)

其中⊙是逐元素乘法

参数量：
- FFN参数占模型总参数的约2/3
- 注意力参数占约1/3

═══════════════════════════════════════════════════════════════════
```

## 三、Flash Attention

### 3.1 标准注意力的内存问题

```
标准注意力内存问题
═══════════════════════════════════════════════════════════════════

标准注意力：Attention(Q,K,V) = softmax(QK^T / √d_k) V

内存复杂度：
- Q,K,V ∈ R^{n×d}：O(nd) 内存
- S = QK^T ∈ R^{n×n}：O(n²) 内存 ← 瓶颈
- P = softmax(S) ∈ R^{n×n}：另一个O(n²)
- O = PV ∈ R^{n×d}：O(nd)

示例（n=8192, d=128, BF16）：
- 注意力矩阵：8192² × 2 ≈ 134MB 每个头
- 32个头：4.3GB 仅一层的注意力分数

为什么O(n²)是灾难性的：
- 注意力矩阵必须写入HBM（不适合SRAM）
- 然后为softmax读回
- 然后再次读取用于PV乘积
- 每次HBM往返都很慢

对于n=32768（32K上下文）：
- 注意力矩阵：32768² × 2 ≈ 2GB 每个头
- 完全不可行存储

═══════════════════════════════════════════════════════════════════
```

### 3.2 Flash Attention核心洞察

```
Flash Attention核心洞察
═══════════════════════════════════════════════════════════════════

核心洞察：我们永远不需要同时在内存中拥有完整的n×n矩阵
我们可以逐块计算输出O，如果使用在线softmax技巧

在线Softmax：
softmax(x_i) = e^{x_i - m} / Σ_j e^{x_j - m}
其中 m = max_j x_j

技巧：我们可以随着处理新块更新运行最大值和归一化因子
无需物化完整行

在线Softmax更新规则：
给定运行状态(m_old, l_old, O_old)和新分数块s_new：
1. m_new = max(m_old, max(s_new))
2. l_new = e^{m_old - m_new} · l_old + Σ_j e^{s_new,j - m_new}
3. O_new = (1/l_new) · (e^{m_old - m_new} · l_old · O_old + e^{s_new - m_new} · V_new)

这在数学上等价于一次计算所有块的softmax

═══════════════════════════════════════════════════════════════════
```

### 3.3 Flash Attention算法

```
Flash Attention前向传播 - 块分块
═══════════════════════════════════════════════════════════════════

设置：SRAM大小M。块大小 B_r = ⌈M/(4d)⌉, B_c = min(⌈M/(4d)⌉, d)

1. 将Q分成 T_r = ⌈n/B_r⌉ 个块 Q_1, ..., Q_{T_r}
2. 将K,V分成 T_c = ⌈n/B_c⌉ 个块 K_1, ..., K_{T_c}
3. 初始化输出O ∈ R^{n×d}，运行最大值m ∈ R^n，运行和l ∈ R^n（都在HBM中）

4. 外循环 j = 1, ..., T_c：
   (a) 从HBM加载K_j, V_j到SRAM
   (b) 内循环 i = 1, ..., T_r：
       i. 从HBM加载Q_i, O_i, m_i, l_i到SRAM
       ii. 计算 S_ij = Q_i K_j^T / √d（保持在SRAM中）
       iii. 应用在线softmax更新得到新的m_i, l_i, O_i
       iv. 将O_i, m_i, l_i写回HBM

5. 返回O

关键：S_ij（注意力块）在SRAM中计算并丢弃
它永远不会写入HBM

═══════════════════════════════════════════════════════════════════
```

### 3.4 Flash Attention复杂度

```
Flash Attention复杂度对比
═══════════════════════════════════════════════════════════════════

指标            │ 标准注意力  │ Flash Attention
────────────────┼─────────────┼────────────────
内存（HBM）     │ O(n²)       │ O(n)
HBM读写         │ O(n²d)      │ O(n²d/M)
FLOPs           │ O(n²d)      │ O(n²d)（相同）
加速            │ 1×          │ 2-4×

关键点：
- 前向传播的总FLOPs保持O(n²d) - 与标准注意力相同
- Flash Attention完全通过削减缓慢的HBM流量获得速度
- 不是通过减少算术
- 反向传播实际上执行更多FLOPs（由于重计算）
- 但墙钟时间仍然更低，因为节省的内存带宽占主导

═══════════════════════════════════════════════════════════════════
```

## 四、优化技术

### 4.1 LoRA（低秩适配）

```
LoRA核心思想
═══════════════════════════════════════════════════════════════════

问题：全参数微调70B模型需要~560GB内存（参数+梯度+优化器状态）

LoRA洞察：微调期间的权重更新是低秩的

方法：
W = W_0 + ΔW = W_0 + BA

其中：
- W_0 ∈ R^{d×d}：预训练权重（冻结）
- B ∈ R^{d×r}：低秩矩阵（可训练）
- A ∈ R^{r×d}：低秩矩阵（可训练）
- r << d：秩（通常r=8-64）

参数效率：
- 原始参数：d²
- LoRA参数：2dr
- 当r=16, d=4096：参数减少128×

示例：
- 70B模型全参数微调：~560GB
- 70B模型LoRA微调（r=16）：~20GB

═══════════════════════════════════════════════════════════════════
```

### 4.2 LoRA超参数

```
LoRA超参数指南
═══════════════════════════════════════════════════════════════════

秩r：
- r=8-16：大多数任务足够
- r=32-64：复杂任务或领域适配
- r=128+：接近全参数微调

目标模块：
- 通常：q_proj, k_proj, v_proj, o_proj（注意力投影）
- 可选：gate_proj, up_proj, down_proj（FFN）
- 全部应用通常效果最好

缩放因子α：
- 通常设置α = 2r
- 控制LoRA更新的幅度
- α/r是有效学习率缩放

 dropout：
- 通常0.05-0.1
- 防止过拟合
- 小数据集时更重要

初始化：
- A：高斯初始化
- B：零初始化（确保开始时ΔW=0）

═══════════════════════════════════════════════════════════════════
```

### 4.3 混合专家（MoE）

```
MoE架构
═══════════════════════════════════════════════════════════════════

核心思想：用稀疏激活替代密集层

标准FFN：
y = FFN(x)  # 所有参数都参与

MoE FFN：
y = Σ_{i=1}^N g_i(x) · E_i(x)  # 只有top-k个专家激活

其中：
- E_i：第i个专家网络（通常是标准FFN）
- g_i(x)：门控网络，决定激活哪些专家
- N：专家总数（通常8-64）
- k：激活的专家数（通常1-2）

门控机制（Top-K）：
g(x) = TopK(softmax(W_g x), k)

优势：
- 参数量大但计算量小
- 例如：671B参数但只有37B活跃（DeepSeek-V3）
- 每个令牌只使用5.5%的参数

挑战：
- 负载均衡：确保专家被均匀使用
- 通信开销：分布式训练中专家可能在不同GPU
- 训练不稳定：门控可能坍缩到少数专家

═══════════════════════════════════════════════════════════════════
```

### 4.4 量化

```
模型量化
═══════════════════════════════════════════════════════════════════

核心思想：用低精度表示替代高精度权重

量化级别：
├── FP32 → FP16/BF16：2×内存减少，几乎无损
├── FP16 → INT8：2×内存减少，轻微损失
├── FP16 → INT4：4×内存减少，明显损失
└── FP16 → INT2/INT3：8×内存减少，显著损失

量化方法：
1. 训练后量化（PTQ）
   - 直接量化已训练模型
   - 简单但可能有质量损失
   - 代表：GPTQ, AWQ

2. 量化感知训练（QAT）
   - 在训练期间模拟量化
   - 更好的质量保留
   - 代表：QLoRA

3. 混合精度
   - 不同层使用不同精度
   - 敏感层保持高精度
   - 平衡质量和效率

QLoRA（4-bit量化 + LoRA）：
- 4-bit NormalFloat量化
- 双重量化（量化常数也被量化）
- 分页优化器
- 70B模型可在单个48GB GPU上微调

═══════════════════════════════════════════════════════════════════
```

## 五、GPU架构

### 5.1 为什么用GPU

```
CPU vs GPU设计哲学
═══════════════════════════════════════════════════════════════════

CPU优化目标：延迟
- 执行少量线程尽可能快
- 大缓存、分支预测、乱序执行
- 现代CPU：8-96核

GPU优化目标：吞吐量
- 并行执行数千线程
- 每个线程做简单工作
- 现代GPU：数千"核"（执行单元）

深度学习工作loads：
- 由矩阵乘法主导（O(n³)操作，O(n²)数据）
- 高度可并行
- 70B模型单次前向传播需要~140 TFLOP/token
- 完美适合GPU吞吐量

═══════════════════════════════════════════════════════════════════
```

### 5.4 GPU内存层次

```
GPU内存层次（A100 80GB参考）
═══════════════════════════════════════════════════════════════════

层次        │ 容量       │ 带宽      │ 延迟    │ 位置
────────────┼────────────┼───────────┼─────────┼────────────────
寄存器      │ ~256 KB/SM │ >100 TB/s │ 1周期   │ 芯片上，每线程
SRAM（共享）│ 164 KB/SM  │ ~19 TB/s  │ ~20周期 │ 芯片上，每SM
L2缓存      │ 40 MB总计  │ ~5 TB/s   │ ~200周期│ 芯片上，共享
HBM2e（VRAM）│ 80 GB     │ 2 TB/s    │ ~200 ns │ 封装上（5栈）
CPU DRAM    │ 512 GB+    │ ~25 GB/s  │ ~10 µs  │ 主机（PCIe 4）
NVMe SSD    │ TBs        │ 7 GB/s    │ ~100 µs │ 主机存储

为什么差距如此大：
- 每个层次大约慢10×，大100-1000×
- A100：312 TFLOP/s BF16，但只有2 TB/s HBM带宽
- 每加载1字节，可以执行~156浮点操作
- 如果内核每字节少于156 FLOPs → 内存受限

═══════════════════════════════════════════════════════════════════
```

### 5.5 算术强度和屋顶模型

```
算术强度和屋顶模型
═══════════════════════════════════════════════════════════════════

算术强度 I = FLOPs / 从HBM访问的字节（FLOPs/Byte）

内核分类：
- I < I_ridge：内存受限
- I > I_ridge：计算受限

A100 BF16的脊点：
I_ridge = 峰值FLOP/s / 峰值带宽
        = 312×10¹² / 2×10¹²
        = 156 FLOP/Byte

注意力算术强度（n=4096, d=128）：
- FLOPs：~8.6 GFLOP
- 内存流量：~138 MB（标准实现）
- I ≈ 62 FLOP/Byte < 156 → 内存受限！

FFN层（大GEMM）：
- 通常是计算受限
- I > 156

关键洞察：
- 注意力是内存受限的
- FFN是计算受限的
- 这解释了为什么Flash Attention（减少内存流量）对注意力如此有效

═══════════════════════════════════════════════════════════════════
```

## 六、vLLM

### 6.1 KV缓存碎片问题

```
KV缓存碎片问题
═══════════════════════════════════════════════════════════════════

问题：标准KV缓存管理导致严重的内存碎片

标准实现：
- 为每个请求预分配最大序列长度的连续内存
- 实际使用可能远小于预分配
- 内存利用率低

碎片化后果：
- 内存浪费（可达60-80%）
- 无法服务更多请求
- 吞吐量降低

═══════════════════════════════════════════════════════════════════
```

### 6.2 PagedAttention

```
PagedAttention
═══════════════════════════════════════════════════════════════════

核心思想：将操作系统的虚拟内存思想应用于KV缓存

方法：
1. 将KV缓存分成固定大小的块（页）
2. 每个请求的KV缓存存储在非连续的块中
3. 使用页表映射逻辑位置到物理块
4. 按需分配块（而非预分配最大长度）

优势：
- 内存利用率接近100%
- 几乎零碎片
- 支持更长序列
- 更高的批处理吞吐量

内存节省示例（70B模型）：
- 标准实现：~60%内存浪费
- PagedAttention：<4%内存浪费
- 吞吐量提升：2-4×

═══════════════════════════════════════════════════════════════════
```

### 6.3 连续批处理

```
连续批处理
═══════════════════════════════════════════════════════════════════

传统批处理：
- 等待批次中所有请求完成
- 短请求等待长请求
- GPU利用率低

连续批处理（也称动态批处理）：
- 请求完成后立即插入新请求
- 不等待整个批次完成
- GPU始终保持忙碌

优势：
- 更高的GPU利用率
- 更低的延迟（短请求不等待）
- 更高的吞吐量

实现：
- 跟踪每个请求的进度
- 动态添加/移除请求
- 管理不同长度的序列

═══════════════════════════════════════════════════════════════════
```

## 七、分布式训练

### 7.1 并行策略概览

```
分布式训练并行策略
═══════════════════════════════════════════════════════════════════

策略1：数据并行（DP/DDP）
├── 每个GPU持有完整模型副本
├── 数据批次分割到不同GPU
├── 梯度在GPU间同步
└── 通信：梯度归约

策略2：张量并行（TP）
├── 单个层分割到多个GPU
├── 矩阵按列或行分割
├── 每个GPU计算部分结果
└── 通信：AllReduce/AllGather

策略3：序列并行（SP）
├── 序列维度分割到多个GPU
├── 不同GPU处理不同序列位置
├── 与TP互补
└── 通信：AllGather

策略4：流水线并行（PP）
├── 模型层分割到不同GPU
├── 不同GPU处理不同层
├── 微批次流水线执行
└── 通信：点对点

策略5：FSDP/ZeRO
├── 优化器状态、梯度、参数分片
├── 每个GPU只持有部分状态
├── 计算时按需收集
└── 通信：AllGather + ReduceScatter

═══════════════════════════════════════════════════════════════════
```

### 7.2 3D并行

```
3D并行组合
═══════════════════════════════════════════════════════════════════

3D并行 = 数据并行 × 张量并行 × 流水线并行

示例（64 GPU训练70B模型）：
- 8路张量并行（TP=8）：每层分割到8个GPU
- 4路流水线并行（PP=4）：模型分成4个阶段
- 2路数据并行（DP=2）：2个模型副本

通信层次：
├── 节点内（NVLink）：高带宽（600-900 GB/s）
│   └── 用于张量并行
├── 节点间（InfiniBand）：中等带宽（200-400 GB/s）
│   └── 用于数据并行和流水线并行
└── 跨机架（以太网）：低带宽（10-100 GB/s）
    └── 尽量避免

最佳实践：
- TP放在节点内（需要最高带宽）
- PP跨节点（通信量较小）
- DP跨节点（梯度同步可异步）

═══════════════════════════════════════════════════════════════════
```

### 8.1 模型架构最佳实践

模型架构最佳实践

   - SwiGLU激活函数
   - 4×扩展因子
   - 考虑MoE用于大模型

   - Pre-Norm（LayerNorm在子层前）
   - RMSNorm（比LayerNorm更快）

```
训练优化最佳实践
═══════════════════════════════════════════════════════════════════

1. 混合精度训练
   - BF16（优于FP16，无溢出问题）
   - FP8（H100+，进一步加速）

   - 使用梯度累积达到目标批量
   - 线性缩放规则
   - 监控梯度噪声

5. 内存优化
   - 梯度检查点（用计算换内存）
