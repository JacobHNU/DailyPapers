## 一、RAG（检索增强生成）(第16章)

### 1.1 为什么LLM需要外部知识

```
LLM的参数化知识局限
═══════════════════════════════════════════════════════════════════

大语言模型将知识参数化 - 压缩到训练期间的数十亿权重中
这产生三个根本限制：

1. 幻觉（Hallucination）
   - 模型自信地生成听起来合理但事实不正确的陈述
   - 当查询超出可靠知识边界时发生

2. 知识过时（Knowledge Staleness）
   - 训练数据有截止日期
   - 模型无法知道训练后发生的事件、论文或产品更新

3. 领域特异性（Domain Specificity）
   - 通用模型缺乏专有代码库、内部文档、专业法规或企业数据的深入知识

═══════════════════════════════════════════════════════════════════
```

### 1.2 参数化 vs 非参数化知识

```
两种知识范式
═══════════════════════════════════════════════════════════════════

参数化知识：
P_parametric(a|q) = P_{M_θ}(a|q)
- 知识编码在模型权重中
- 更新需要重新训练
- 无法引用来源

非参数化知识（RAG）：
P_RAG(a|q,D) = Σ_{d∈D} P_{M_θ}(a|q,d) P_ret(d|q,D)
- 知识存储在外部文档D中
- 可以实时更新
- 可以引用来源

图书馆类比：
参数化LLM就像一个记住了巨大图书馆但多年前毕业的学者
RAG给那个学者一张图书馆卡 - 他们可以实时查找、引用来源，
并承认需要检查参考而不是从记忆中猜测

═══════════════════════════════════════════════════════════════════
```

### 1.3 RAG vs 微调 vs 长上下文

```
RAG vs 微调 vs 长上下文决策指南
═══════════════════════════════════════════════════════════════════

标准              │ RAG │ 微调 │ 长上下文 │ RAG+微调
──────────────────┼─────┼──────┼──────────┼──────────
知识频繁更新       │ ✅  │ ❌   │ ❌       │ ✅
需要引用/依据      │ ✅  │ ❌   │ ✅       │ ✅
专有大语料库       │ ✅  │ ❌   │ ❌       │ ✅
适应风格/格式      │ ❌  │ ✅   │ ❌       │ ✅
教授新推理技能     │ ❌  │ ✅   │ ❌       │ ✅
语料适合上下文窗口 │ ❌  │ ❌   │ ✅       │ ❌
低延迟要求         │ ❌  │ ✅   │ ❌       │ ❌

常见误解：
RAG不是微调的替代品
- 微调教会模型如何推理和响应
- RAG提供推理的内容
- 它们是互补的

═══════════════════════════════════════════════════════════════════
```

### 1.4 核心RAG架构

```
RAG端到端架构
═══════════════════════════════════════════════════════════════════

离线索引管道（蓝色）：
┌─────────────────────────────────────────────────────────────────┐
│ 文档加载 → 分块 → 嵌入 → 存储到向量数据库                      │
└─────────────────────────────────────────────────────────────────┘

在线检索-生成管道（绿色/橙色）：
┌─────────────────────────────────────────────────────────────────┐
│ 查询 → 查询嵌入 → 相似度检索 → Top-K文档 → 提示构建 → LLM生成  │
└─────────────────────────────────────────────────────────────────┘

详细步骤：

1. 文档加载（Document Loading）
   - 异构格式（PDF、HTML、Markdown、DOCX、代码）
   - 提取干净文本并保留元数据（源URL、页码、章节标题、时间戳）

2. 分块（Chunking）
   - 长文档必须分成适合嵌入模型上下文窗口的块（通常512令牌）
   - 语义连贯性
   - 分块策略是RAG系统设计中影响最大的决策之一

3. 嵌入（Embedding）
   - 每个块c_i编码为密集向量e_i = f_φ(c_i) ∈ R^d
   - 使用嵌入模型f_φ
   - 向量与原始文本和元数据一起存储在向量数据库中

4. 检索（Retrieval）
   - 查询q编码为q = f_φ(q)
   - 按余弦相似度找到最相似的k个块
   - sim(q, e_i) = q·e_i / (||q|| ||e_i||)
   - 返回top-k块作为上下文

5. 生成（Generation）
   - 检索到的块注入提示模板
   - LLM基于上下文生成答案
   - 包含引用来源

═══════════════════════════════════════════════════════════════════
```

### 1.5 检索方法

```
检索方法全景
═══════════════════════════════════════════════════════════════════

方法1：稀疏检索（BM25和TF-IDF）

BM25评分函数：
BM25(d,q) = Σ_{i=1}^n IDF(t_i) · f(t_i,d) · (k_1+1) / (f(t_i,d) + k_1 · (1-b+b·|d|/avgdl))

其中：
- f(t_i,d)：词频
- |d|：文档长度
- avgdl：平均文档长度
- k_1 ∈ [1.2,2.0]，b = 0.75：调优参数

稀疏检索仍然有效的场景：
├── 精确关键词匹配：产品代码、错误代码、专有名词、罕见术语
├── 低资源领域：密集模型训练数据不足
├── 可解释性：容易调试为什么检索到某个文档
├── 速度：不需要GPU；使用倒排索引可扩展到数十亿文档
└── 词汇外术语：嵌入训练期间未见过的新术语

方法2：密集检索（DPR）

双编码器架构：
sim(q,p) = E_Q(q)^T E_P(p)

批内负样本训练：
L_DPR = -(1/B) Σ_{i=1}^B log [exp(E_Q(q_i)^T E_P(p_i)/τ) / Σ_{j=1}^B exp(E_Q(q_i)^T E_P(p_j)/τ)]

近似最近邻搜索（ANN）：
├── IVF（倒排文件索引）：将向量聚类到Voronoi单元；只搜索单元附近
├── HNSW（分层可导航小世界）：基于图的索引，O(log N)搜索
└── PQ（乘积量化）：压缩向量减少内存占用

方法3：学习稀疏检索（SPLADE）

SPLADE核心思想：
- 使用预训练MLM模型（如BERT）为每个文档/查询产生稀疏向量
- 在整个词汇表上
- 结合稀疏检索的速度和密集检索的语义理解

SPLADE评分：
w_t(x) = log(1 + ReLU(max_{i∈[1,n]} H_i[t]))

其中H_i[t]是输入位置i处词汇令牌t的MLM logit

优势：
- 词汇扩展：原始文本中不存在的令牌也可以获得非零权重
- 稀疏性：大多数词汇令牌权重为零
- 高效：使用倒排索引快速检索

方法4：晚期交互（ColBERT）

ColBERT使用双编码器但保留令牌级表示：
- 查询和文档分别编码为令牌嵌入序列
- 相似度通过最大相似度之和计算
- 比DPR更精确，比交叉编码器更快

═══════════════════════════════════════════════════════════════════
```

### 1.6 混合检索与倒数排名融合

```
混合检索
═══════════════════════════════════════════════════════════════════

问题：稀疏和密集检索的分数不可直接比较

解决方案：倒数排名融合（RRF）

RRF(d) = Σ_{r∈R} 1/(k + rank_r(d))

其中：
- R：排序列表集合（如BM25排序和密集排序）
- rank_r(d)：文档d在列表r中的排名
- k = 60：平滑常数

RRF计算示例：
假设BM25将文档d排在位置3，密集检索排在位置7
k = 60：

RRF(d) = 1/(60+3) + 1/(60+7) = 1/63 + 1/67 ≈ 0.0159 + 0.0149 = 0.0308

在两个列表中都排第1的文档得分：1/61 + 1/61 ≈ 0.0328

关键洞察：
混合检索始终优于单独使用任一方法

═══════════════════════════════════════════════════════════════════
```

### 1.7 分块策略

```
分块策略
═══════════════════════════════════════════════════════════════════

策略1：固定大小分块（带重叠）
- 最简单的方法
- 每个块固定数量的令牌（如512）
- 重叠区域（如50令牌）保持连续性
- 问题：可能切断句子或段落

策略2：语义分块
- 基于语义相似性分割
- 在主题变化处分割
- 更连贯的块
- 实现更复杂

策略3：文档结构感知分块
- 利用文档结构（标题、段落、列表）
- 每个部分作为独立块
- 保留层次信息
- 适合结构化文档

策略4：父-子分块
- 小块用于精确检索
- 大块（父块）提供上下文
- 检索小块但返回父块
- 平衡精确性和上下文

分块大小经验指南：
├── 128-256令牌：精确检索，适合Q&A
├── 512令牌：通用目的，平衡精确性和上下文
├── 1024+令牌：需要更多上下文的任务（摘要、分析）
└── 动态大小：根据内容复杂度调整

═══════════════════════════════════════════════════════════════════
```

### 1.8 高级RAG模式

```
高级RAG模式
═══════════════════════════════════════════════════════════════════

模式1：查询转换（Query Transformation）
├── 查询重写：将模糊查询重写为更精确的形式
├── 查询扩展：生成多个相关查询
├── 子问题分解：将复杂问题分解为子问题
└── 回退提示：生成更抽象的问题

模式2：重排序（Re-Ranking）
├── 初始检索返回k' >> k个候选
├── 交叉编码器对每个(查询, 文档)对评分
├── 返回top-k最相关的
└── 更精确但更慢

模式3：上下文压缩（Contextual Compression）
├── 检索后压缩文档
├── 只保留与查询相关的部分
├── 减少上下文窗口使用
└── 提高答案质量

模式4：Self-RAG
├── 模型决定何时检索
├── 生成特殊令牌表示检索需求
├── 评估检索相关性
└── 评估生成质量

模式5：CRAG（纠正RAG）
├── 检索后评估文档相关性
├── 如果相关性低，触发网络搜索
├── 知识精炼去除噪声
└── 生成基于精炼知识的答案

模式6：自适应RAG（Adaptive RAG）
├── 根据查询复杂度选择策略
├── 简单问题：直接生成
├── 中等问题：单次检索
└── 复杂问题：多步检索+推理

模式7：Graph RAG
├── 使用知识图谱增强检索
├── 实体和关系检索
├── 图遍历发现相关概念
└── 结构化和非结构化知识结合

模式8：RAG-Fusion
├── 生成多个查询变体
├── 对每个变体检索
├── 融合所有检索结果
└── 重排序最终结果

═══════════════════════════════════════════════════════════════════
```

## 二、奖励模型 (第9章)

### 2.1 Bradley-Terry模型

```
Bradley-Terry模型
═══════════════════════════════════════════════════════════════════

核心思想：将偏好建模为两个项目之间的比较

数学模型：
P(y_w ≻ y_l) = σ(r(y_w) - r(y_l))

其中：
- y_w：优选响应（winner）
- y_l：劣选响应（loser）
- r(y)：奖励函数
- σ：sigmoid函数

训练目标：
L = -E_{(x,y_w,y_l)} [log σ(r(y_w) - r(y_l))]

直觉：
- 如果r(y_w) >> r(y_l)：损失接近0（正确排序）
- 如果r(y_w) ≈ r(y_l)：损失≈0.69（不确定）
- 如果r(y_w) << r(y_l)：损失很大（错误排序）

奖励模型架构：
通常使用与策略相同的Transformer骨干
替换语言建模头为标量奖励头
在最后一个令牌的隐藏状态上回归

═══════════════════════════════════════════════════════════════════
```

### 2.2 过程奖励模型 vs 结果奖励模型

```
PRM vs ORM
═══════════════════════════════════════════════════════════════════

结果奖励模型（ORM）：
R_ORM(q, y) ∈ [0,1]
- 对完整响应评分
- 只在序列结束时给出奖励
- 训练数据容易收集（只需最终答案对错）
- 信号稀疏（对长推理链）

过程奖励模型（PRM）：
R_PRM(q, y, t) ∈ [0,1]
- 对推理的每个步骤评分
- 提供密集的训练信号
- 可以识别具体错误步骤
- 训练数据昂贵（需要步骤级标注）

PRM优势：
- 更细粒度的反馈
- 更好的信用分配
- 可以检测中间错误
- 对长推理链更有效

PRM劣势：
- 需要步骤级标注（昂贵）
- 可能引入步骤级奖励黑客
- 训练更复杂
- 标注一致性挑战

DeepSeek-R1的发现：
无需PRM，仅结果奖励足以让RL发现高质量推理策略
数学/代码奖励的可验证性质提供了足够的信号

═══════════════════════════════════════════════════════════════════
```

### 2.3 基于规则的奖励（RLVR）

```
RLVR：基于规则的奖励
═══════════════════════════════════════════════════════════════════

核心思想：使用确定性规则计算奖励，无需学习的奖励模型

适用场景：
- 数学问题：答案可验证
- 代码问题：测试用例可执行
- 逻辑问题：正确性可检查

数学问题奖励：
r(y, y*) = 1 if verify(y, y*) = True
         = 0 otherwise

代码问题奖励：
r(y, T) = (1/|T|) Σ_{t∈T} 1[execute(y, t) = expected(t)]

格式奖励（DeepSeek-R1）：
r_fmt(y) = 1 if y has valid <think> and <answer> tags
         = 0 otherwise

组合奖励：
r(y, y*) = r_acc(y, y*) + λ_fmt · r_fmt(y)

优势：
- 无需训练奖励模型
- 奖励信号准确
- 避免奖励模型偏差
- 计算高效

劣势：
- 只适用于可验证任务
- 对开放式任务不适用
- 可能过于稀疏

═══════════════════════════════════════════════════════════════════
```

### 2.4 多目标奖励

```
多目标奖励组合策略
═══════════════════════════════════════════════════════════════════

问题：实际应用通常需要平衡多个目标

目标示例：
- 正确性：答案是否正确
- 有用性：是否有帮助
- 安全性：是否无害
- 格式：是否符合要求
- 长度：是否适当

组合策略：

策略1：线性加权
r_total = Σ_i w_i · r_i
- 简单直观
- 需要手动调权重
- 可能掩盖单个目标问题

策略2：约束优化
max r_primary
s.t. r_i >= threshold_i for all i
- 确保所有目标满足最低要求
- 主目标最大化
- 更实际

策略3：层次化
首先确保安全性
然后确保正确性
最后优化有用性
- 符合实际优先级
- 可以早期过滤有害输出

策略4：动态权重
根据上下文调整权重
- 高风险场景：安全性权重更高
- 代码生成：正确性权重更高
- 创意写作：有用性权重更高

DeepSeek-R1示例：
r = r_acc + 0.1 · r_fmt
- λ_fmt = 0.1足够小不主导
- 足够大防止格式崩溃

═══════════════════════════════════════════════════════════════════
```

### 2.5 奖励模型训练技巧

```
奖励模型训练技巧
═══════════════════════════════════════════════════════════════════

1. 数据质量
   - 偏好数据质量比数量更重要
   - 确保标注者一致性（κ > 0.6）
   - 平衡正负样本比例
   - 包含多样化示例

2. 架构选择
   - 通常与策略模型共享骨干
   - 奖励头：简单的线性层
   - 考虑使用较小模型（降低成本）

3. 训练配置
   - 学习率：比策略训练低（1e-5到5e-6）
   - 批量大小：32-128
   - 训练轮数：1-3轮（避免过拟合）
   - 正则化：权重衰减、dropout

4. 避免过度优化
   - 监控奖励分布
   - 检测奖励黑客
   - 定期用新数据重新训练
   - 使用KL惩罚限制策略偏离

5. 评估奖励模型
   - 准确率：偏好预测准确率
   - 校准：预测概率与实际一致性
   - 鲁棒性：对抗性输入测试
   - 泛化：分布外数据表现

### 3.6 LLM-as-Judge

```
LLM-as-Judge
═══════════════════════════════════════════════════════════════════

核心思想：使用LLM自动评估LLM输出

校准：
当使用LLM生成评估标签时，校准至关重要
评判者的分数必须与人类判断对齐

期望校准误差（ECE）：
ECE = Σ_{b=1}^B (|B_b|/n) · |acc(B_b) - conf(B_b)|

其中：
- B_b：第b个置信度区间
- acc(B_b)：区间中评判者与人类一致的比例
- conf(B_b)：区间中评判者的平均置信度

良好校准的评判者满足：
E[ĥ_i | ĥ_i = p] = p 对所有p ∈ [0,1]

校准改进：
温度缩放：用z/T替代原始logit z
T在保留校准集上调整以最小化负对数似然

LLM-as-Judge最佳实践：
├── 使用多个评判者（减少偏差）
├── 详细评估标准（明确rubric）
├── 示例驱动（提供标注示例）
├── 监控一致性（评判者间一致性）
└── 定期校准（与人类判断对齐）

═══════════════════════════════════════════════════════════════════
```

### 3.7 合成数据生成

```
合成数据生成方法
═══════════════════════════════════════════════════════════════════

方法1：Self-Instruct
从种子任务集引导指令跟随数据
1. 维护用175个种子任务初始化的任务池
2. 从池中采样8个任务作为少样本示例
3. 提示LLM生成新任务
4. 过滤：移除近重复、分类 vs 非分类
5. 为新任务生成输入-输出实例
6. 重复直到达到所需池大小

方法2：Evol-Instruct
通过迭代重写指令使其更复杂或更多样
├── 深度进化：添加约束、增加推理步骤、具体化抽象
└── 广度进化：生成相关但不同主题的新指令

方法3：Constitutional AI
根据一组原则（"宪法"）让模型批评和修订自己的输出
1. 监督学习阶段：
   - 采样有害提示
   - 生成初始响应
   - 提示模型根据宪法原则批评响应
   - 使用修订后的响应作为SFT目标
2. RL阶段：
   - 生成响应对（原始 vs 修订）
   - 使用模型标注哪个更符合宪法
   - 在这些标签上训练偏好模型
   - 使用偏好模型作为RL的奖励信号

方法4：蒸馏
使用强大模型生成评估数据
- 从GPT-4/Claude生成高质量响应
- 用于评估较弱模型
- 或用于训练数据
